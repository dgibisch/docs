everydeck speaks in plain words by default. The **developer view** adds the technical details next to them, on every page.

- **Off** (the default): plain words, technical sections folded.
- **On:** the same pages, with the technical sections open. Values that are otherwise only a tooltip appear as a line in code font. A tinted strip says: "Developer view: technical detail is shown everywhere. Press D to turn it off."

With the developer view on, you also get:

- the tab **Developer** in the settings of each app, with the app map, coverage, heartbeats and reachability, background jobs, code changes, the tools for a setup session and **System map**: "Parts of Acme and how they connect, from the code", **Scope**: "Which flows of Acme everydeck recognizes and which it has seen" and **Activity**: "Notable events in Acme per hour and flow". See [App parts and heartbeats](/using/app-parts-and-heartbeats).
- **Logs** in the side bar of the app, under Operations.

## Turning it on

- Use the switch **Developer view** at the top right of every page of an app, on **Your apps**, in **Settings** and in the menu behind your profile picture.
- Or press the **D** key. It does nothing while you type in a field, or with Cmd, Ctrl or Alt.
- In **Settings › Profile**, under **Display**, it is called **Developer view**: "Shows file names, routes and technical details next to plain words, and the Developer tab in each app’s settings."

The setting is saved with your account, so it holds on every device. If saving fails, the old state comes back with "Developer view could not be saved. Try again."

## Who has it

Only roles that may see code: Owner, Admin, Agency and Viewer. Support has no switch and no D key. See [Team and roles](/using/team-and-roles).

The developer view shows nothing your role may not see. It only opens what is already there.

## Cases from the setup

Cases from the time while your app was being set up move to the developer view once your app sends real data.
